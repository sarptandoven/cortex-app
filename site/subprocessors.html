Subprocessors

Draft — pending legal review before public launch. This list is written to reflect the stack Cortex Cloud actually uses or plans to use. Provider names marked (confirm) are the operator's choice and must be confirmed before this page is published. The operating entity is [LEGAL ENTITY NAME].

A "subprocessor" is a third party that processes Cortex Cloud user data on our behalf. The local app uses no subprocessors — it runs entirely on your Mac. The table below applies only to the optional hosted Cortex Cloud tier. See the Privacy page for how data is handled overall.

Current subprocessors

Subprocessors for Cortex Cloud. Last updated [DATE].
Provider Purpose Data it touches When it applies
Hetzner Online GmbH Cloud hosting and infrastructure — runs the servers and stores all Cortex Cloud application data and backups. All hosted user data: account records, encrypted connector credentials, memory content and derived indexes, backups. Always (hosted tier).
Postmark (confirm) — or Amazon SES (confirm) Transactional email — sends verification, password-reset, and account emails. Your email address and the contents of those transactional messages. No memory content. When email verification/reset is enabled (public launch).
Paddle (confirm) — or Stripe (confirm) Payments and billing (merchant of record where applicable). Your email and payment/subscription metadata. Card details are handled by the provider, not stored by Cortex. Only if a paid tier is enabled. Not used while Cortex is free.
Cloud AI model provider (confirm — usually none) Generating embeddings or model output, if the operator enables a cloud model instead of the on-device default. The memory content sent for embedding or processing. Only if the operator enables a cloud AI model. The default deployment uses on-device model2vec embeddings and sends nothing to a third-party AI processor.

By default the hosted deployment generates embeddings on-device with the model2vec model, so no third-party AI processor is involved. A cloud AI provider appears on this list only if the operator turns one on; if none is enabled, the last row does not apply.
