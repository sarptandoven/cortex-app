CORTEX UNIQUE VALUE AND 10K-USER ROADMAP
Generated: 2026-07-01

SUMMARY

Cortex should not be positioned as another notes app, search app, or AI chat wrapper.
The bigger product is a personal intelligence layer between a user's life and every AI tool.

The simplest framing:

Connect your life once. Cortex turns it into a private, self-updating intelligence layer that makes every AI tool work like it actually knows you.

The product should automatically understand:
- what the user knows
- how the user writes
- what the user cares about
- what projects are active
- what decisions were made
- what promises were made
- what relationships matter
- what procedures the user follows
- what the user dislikes or rejects
- what is currently true versus stale

Then Cortex safely lends that context to AI tools, agents, and workflows through MCP and app integrations.

Cortex should avoid becoming:

Cortex should become:

CORE VALUE PROPOSITION

Cortex gives users three things that are hard to get elsewhere:

1. Personal continuity
AI tools stop treating every session as a cold start. Claude, ChatGPT, Codex, and future agents can ask Cortex for exactly the context they need.

2. Trustworthy memory
Cortex does not just remember. It cites sources, tracks where facts came from, shows why memory was used, and lets users revoke or correct it.

3. Action-ready context
Cortex prepares the right context before the user acts: before meetings, emails, coding, writing, decisions, follow-ups, and agent tasks.


UNIQUE PRODUCT PILLARS

1. PERSONAL CONTEXT API

Cortex should become the API for "what should AI know about me right now?"

Examples:
- What context does Claude need before editing this PR?
- How does this user usually write investor updates?
- What did the user decide about pricing last month?
- What promises did the user make to this person?
- What open loops exist for this project?
- What should ChatGPT know before drafting this reply?

MCP is a strong output path because it lets external model hosts call tools exposed by Cortex.
Reference: https://modelcontextprotocol.io/specification/2025-06-18/server/tools


2. USER TWIN, NOT CHATBOT TWIN

The goal is not to make a clone that chats like the user.
The goal is to build a working model of the user that helps agents do useful work.

The user model should include:
- writing style
- decision patterns
- project context
- relationship context
- goals
- constraints
- preferences
- negative preferences
- recurring procedures
- active priorities
- trust boundaries

This lets an agent draft, summarize, reply, plan, code, and prioritize in ways that feel materially closer to the user.


3. MEMORY THAT UPDATES ITSELF

Most AI memory is append-only. Cortex should be self-editing.

Memory should support:
- valid_from
- valid_to
- superseded_by
- source trust
- confidence
- relationship to entities/projects
- review status
- archival
- correction
- contradiction detection

Examples:
- "I prefer short technical answers" can remain durable.
- "Use Linear for roadmap tracking" can be superseded if the team moves to Jira.
- "Project Atlas launches next week" should expire after launch.
- "Pricing is $19/month" should be replaced if a later decision changes it.

The major product difference:
AI does not just know old facts. It knows what is currently true and can prove why.


4. CONTEXT FIREWALL

Cortex should be the permission and trust layer between private data and external AI.

Every context output should answer:
- what memory was used?
- from what source?
- why was it allowed?
- what was withheld?
- what app requested it?
- can the user revoke it?
- can the user delete it?

This is essential if users connect email, chat, docs, calendar, GitHub, Notion, and personal notes.


5. PRE-WORK INTELLIGENCE

Cortex should not only answer search questions. It should prepare context before work starts.

Examples:
- before a meeting: last conversation, open loops, relationship notes, likely agenda
- before writing email: recipient history, tone, promises, constraints
- before coding: repo decisions, style preferences, product direction, relevant issues
- before asking Claude/ChatGPT: inject project context and user preferences automatically
- before planning: decisions, goals, blockers, tasks, unresolved questions

This is more useful than search because users often do not know what they need to search for.

PRODUCT EXPERIENCE PRINCIPLES

1. Automatic by default
Users should not manually upload data as the main product model. They should connect sources once, and Cortex should sync.

2. Review only what matters
The app should not become an inbox of extracted fragments. Review should prioritize memories that are useful, risky, contradictory, or high leverage.

3. Ask with citations
Answers should cite sources or abstain. This builds trust and helps users debug memory.

4. Minimal visible controls
The app should feel closer to Wispr Flow's restraint than an admin dashboard.

5. Trust is a first-class surface
Privacy, permissions, source access, deletion, and audit logs should be understandable.

6. Local-first credibility
For the first users, local-first is a differentiator. Hosted sync can come later, but privacy posture should remain core.

PHASE 3: RETRIEVAL AND CONTEXT ASSEMBLY

Goal:

Retrieval signals:

- vector similarity
- recency
- importance
- source trust
- review status
- active project
- entity relation
- temporal validity
- user permissions
- app requesting context
- task type

Hybrid search:
For local-first, keep SQLite + FTS + vector extension.
sqlite-vec is relevant because it runs embedded with SQLite.
Reference: https://github.com/asg017/sqlite-vec

For hosted 10k-user scale, use Postgres + pgvector + full-text search.
pgvector supports vector similarity inside Postgres and can be combined with Postgres FTS for hybrid retrieval.
Reference: https://github.com/pgvector/pgvector

Context assembly:
Given a user task, Cortex should build a context pack with:
- minimal relevant facts
- current project state

- procedures
- style hints
- constraints
- citations

Output should be token-budgeted and permission-scoped.

DIFFERENTIATION

Against notes apps:
Cortex is automatic, source-backed, and agent-facing.

Against meeting note apps:
Cortex spans all sources, not just meetings.

Against AI chat memory:
Cortex is inspectable, cited, permissioned, and cross-tool.

Against RAG/search apps:
Cortex models the user, time, decisions, relationships, procedures, and preferences.

Against always-recording products:
Cortex can be local-first, connector-first, and privacy-forward.

Against CRM/project tools:
Cortex is personal, adaptive, and works across tools rather than replacing them.
