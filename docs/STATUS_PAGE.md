# Cortex Status Page (status.trydoppl.com)

A public status page so users can check whether Cortex is up before filing
support. It runs for free on GitHub Actions + GitHub Pages using
[Upptime](https://upptime.js.org): GitHub Actions probes the endpoints on a
schedule, commits the results back to the repo, and publishes a static status
site to Pages.

This is a **scaffold**. Upptime lives in its own dedicated repository, so the
files here are meant to be copied into that repo — nothing in this repo runs
Upptime. See `status/` for the ready-to-use config.

## What we monitor

Only two endpoints, intentionally minimal:

- `https://api.trydoppl.com/ready` — the API readiness probe (200 = serviceable).
- `https://trydoppl.com` — the public website.

Defined in `status/.upptimerc.yml`.

## Files in this repo

```text
status/
  .upptimerc.yml              # Upptime config -> copy to the status repo ROOT
  workflows/
    uptime.yml                # probes endpoints every 5 min
    response-time.yml         # daily response-time samples
    graphs.yml                # daily response-time graphs
    static-site.yml           # rebuilds + deploys the status site
    summary.yml               # regenerates the README status table
```

## Setup (founder — one time)

Depends on DECISION 0 (the canonical org) and F4 (org Actions/Pages enabled) in
`docs/REMAINING_LAUNCH_WORK.txt`.

1. **Create the status repo in the org.** The Upptime convention is a dedicated
   public repo, e.g. `doppl-tech/status`. Public is required for free Pages and
   so the status page is publicly readable.

2. **Copy the scaffold into it.**
   - `status/.upptimerc.yml` -> repo root as `.upptimerc.yml`.
   - `status/workflows/*.yml` -> `.github/workflows/` in the status repo.
   - Edit `.upptimerc.yml`: set `owner`/`repo` to the actual status repo, and
     `assignees` to the GitHub handles that should be notified (Upptime opens a
     GitHub issue when a monitor goes down and closes it on recovery).

   Alternatively, bootstrap from Upptime's template repo
   (`upptime/upptime`) with "Use this template", then drop this
   `.upptimerc.yml` over the template's default one and keep the template's
   workflows (they match the versions scaffolded here).

3. **Add the `GH_PAT` secret.** Upptime commits results back and (optionally)
   sets the Pages CNAME, so it needs a Personal Access Token, not the default
   `GITHUB_TOKEN`.
   - Create a token with `repo` scope (classic) — or a fine-grained token scoped
     to the status repo with **Contents: read/write**, **Issues: read/write**,
     and **Pages: read/write**.
   - Status repo -> Settings -> Secrets and variables -> Actions -> New
     repository secret -> name `GH_PAT`, value = the token.

4. **Run the workflows once.** In the status repo -> Actions, run **Uptime CI**
   (and optionally the others) via "Run workflow". The scheduled crons then take
   over (uptime every 5 minutes; the rest daily). New GitHub repos need Actions
   enabled: Settings -> Actions -> General -> Allow all actions.

5. **Enable GitHub Pages.** After the first **Static Site CI** run creates the
   `gh-pages` branch: Settings -> Pages -> Source = `gh-pages` branch, `/`
   (root). Then add the custom domain `status.trydoppl.com` (this matches the
   `cname` in `.upptimerc.yml`).

6. **Point DNS at Pages.** In `trydoppl.com` DNS, add a `CNAME` record:
   name `status`, value `<org>.github.io` (e.g. `doppl-tech.github.io`). Wait
   for it to resolve, then Pages will issue the HTTPS certificate.

## Verifying

- The status repo's Actions tab shows green **Uptime CI** runs every ~5 minutes.
- The repo `README.md` shows a live status/uptime table (generated by Summary CI).
- `https://status.trydoppl.com` loads the status site (after Pages + DNS).
- Kill the API briefly (or point a monitor at a bad URL in a test) and confirm
  Upptime opens a downtime issue and marks the monitor down.

## Notes

- Keep the monitor list to `/ready` and the site. `/ready` is the right API
  signal because it reflects dependency serviceability, not just process
  liveness (`/health`).
- This is independent of, and complementary to, an external prober like
  UptimeRobot (founder task F11): UptimeRobot pages you fast; Upptime gives users
  a public history page.
- Pin the `upptime/uptime-monitor` action version in the workflows (done:
  `@v1.35.0`) so a status-page action update can't silently change behavior;
  bump it deliberately.
