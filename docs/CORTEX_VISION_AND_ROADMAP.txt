  3. States what users really want and the single sharpest wedge.

  5. Lays out a phased, concrete roadmap that stays DEAD SIMPLE for users.

--------------------------------------------------------------------------------
0. THE ONE LINE
--------------------------------------------------------------------------------
Cortex is your private memory that lives with YOU, not inside any one AI app —
it quietly learns you from the tools you already use, and hands every AI
(Claude, ChatGPT, Cursor, whatever's next) the exact, cited context it needs to
act like it actually knows you.

Positioning: "Connect once. Every AI knows you. You own the memory, and you can
see and delete everything it knows."

The wedge (why this, why now): the big platforms are racing to add memory, but
each one is a WALLED GARDEN. ChatGPT's memory only works in ChatGPT. Claude's
only works in Claude (and only inside a Project). None of them share, none of
them export cleanly, and you re-teach every new tool from zero — forever. Cortex
is the ONE neutral, portable, user-owned memory that spans all of them. That is
the thing no platform will ever build, because their memory exists to lock you
in, and ours exists to set you free.

--------------------------------------------------------------------------------
1. WHERE WE ARE — HONEST PROJECT ANALYSIS
--------------------------------------------------------------------------------
What we've built (and it's real, not vapor):
  - A native macOS app + local FastAPI backend on 127.0.0.1:8766. Simple surface:
    Home / Review / Ask, with Connections & Privacy behind one sheet.
  - A genuinely differentiated MEMORY MODEL: layered (semantic, episodic, style,
    decision, preference, negative, procedural) + sectors/projects, provenance,
    temporal validity (valid_from/valid_to), supersession, entity + relation
    tables, relationship-memory v1, a decision-ledger direction.
  - Hybrid retrieval: FTS5 + vector + reciprocal-rank fusion + bounded
    deterministic reranking (recency/importance/source-trust/layer-intent/
    confidence), citations-or-abstain, per-layer eval metrics, a CI regression
    gate, and an adversarial safety eval corpus.
  - 13 real connectors with incremental sync, backoff, dedupe, stable citations,
    and no-delete-on-disconnect: Obsidian, GitHub, Slack, Gmail, Google Drive,
    Notion, Outlook, Linear, Jira, Readwise, Raindrop, Zotero, Calendar.
  - An MCP output layer with scoped tools + Trust controls + per-query audit and
    scoped cxm_/cxa_ tokens.
  - A hosted multi-tenant plane on sharded SQLite: provisioning, tenant
    isolation, suspension, LRU store cache, O(1) token auth, worker
    auto-discovery, per-user rate limits + quotas.
  - ~578 backend tests, codesign verification, DMG packaging, a real eval gate.

This is a strong, unusually clean foundation. The team's instinct to stay
local-first, connector-first (no manual upload as primary), and citation-backed
is exactly right and is the source of the moat.

THE THREE HARD TRUTHS we have to face:

  (A) Our "semantic" memory is not actually semantic yet.
      backend/app/embeddings.py ships a SHA-256 hash-bucket vector as the default
      ("cortex-hash-v1"). It is deterministic and offline, but it captures token
      overlap, NOT meaning. Real semantic search only turns on if the user
      supplies an OpenAI API key — which breaks the local-first promise that is
      our whole reason to exist. So today's retrieval is essentially good keyword
      search + clever tiny boosts. This is the single biggest gap between what we
      SAY (a personal memory model) and what we DO. It is also our biggest
      opportunity (see Section 5, item 1).

  (B) We keep re-litigating the product instead of shipping the wedge.
      The transcripts show weeks of backend hardening (connector error taxonomies,
      data-loss audits, hosted plane, rate limits) — all good — but the UNIQUE,
      demoable, "holy-shit" user moment (an external AI tool visibly getting
      smarter about you, live) has never been the north star of a release. We've
      optimized reliability of a loop most users have never felt.

  (C) storage.py is an 18,128-line, 323-method god object.
      Not dead code, but a maintainability tax that will slow every future
      feature. It's a deliberate refactor, not a cleanup — but it must happen
      before the codebase doubles again.

Net: we have a great engine and a fuzzy product. The next era is about making
the engine SEMANTIC (real embeddings), making the value VISIBLE (the AI-gets-
smarter moment), and making the surface RUTHLESSLY SIMPLE.

2. THE COMPETITION — FULLY MAPPED (verified July 2026)
--------------------------------------------------------------------------------
There are five camps. We are not really in any of them — that's the point — but
we must know each cold.

CAMP 1: NATIVE PLATFORM MEMORY (the existential threat, and our biggest opening)
  - ChatGPT Memory: global memory + custom instructions, works ONLY in ChatGPT.
    No clean "export just my memories" file. Locked in.
  - Claude Memory: scoped to individual Projects (Project Knowledge + system
    prompt), NO global cross-chat memory, no dedicated export. Supports MCP.
  - Gemini/Gems, Copilot, Cursor/Windsurf "rules" & memory: each remembers you
    inside its own product only.
  THE KEY FACT (verified): "every tool keeps memory in its own walled garden, and
  migrating every six months turns upkeep into permanent busywork... each
  vendor's memory is a retention feature for its own product, not a portable
  record." This is the crack we drive through. Platforms will NEVER make their
  memory neutral and portable — it's against their business model.
  OUR ANSWER to "why pay when ChatGPT remembers me free?": because it only
  remembers you THERE, it forgets when you switch tools, it can't see your Gmail/
  Slack/Notion/GitHub, and you can't inspect or move it. Cortex is the memory you
  KEEP when you change tools.

CAMP 2: DEVELOPER MEMORY INFRASTRUCTURE (adjacent; not a consumer product)
  - mem0: vector-first memory layer you bolt onto an agent stack. OSS core; graph
    memory gated behind Pro ($249/mo). Dev infra.
  - Zep + Graphiti: temporal knowledge graph for facts-that-change. Graphiti is
    Apache-2.0 OSS (the engine); Zep Cloud is the commercial managed service
    ($25–$475/mo). Dev infra — but Graphiti's temporal patterns are a gift to us.
  - Letta (ex-MemGPT): full agent runtime with self-editing memory; fully OSS,
    self-hostable. Infra, not a product.
  Takeaway: these are picks-and-shovels for developers. We are the consumer/
  prosumer PRODUCT that a normal person installs. We can borrow their best ideas
  (temporal graph, self-editing memory) without competing on their turf.

CAMP 3: OPEN-SOURCE PERSONAL AI / SECOND BRAIN (closest philosophical cousins)
  - Khoj (~30k+ stars): OSS self-hostable "AI second brain," RAG over your docs/
    notes/GitHub, automations, works with local LLMs. But it's a SELF-HOSTED
    ASSISTANT you chat with — it replaces your AI, it doesn't make your existing
    AIs smarter. Setup is technical.
  - Reflect, Mem.ai, Saga, Notion AI, Obsidian+Smart Connections: notes-first;
    you still do the organizing.
  Takeaway: they make a NEW place to think. We make the tools you ALREADY use
  (Claude/ChatGPT/Cursor) think better about you. Different job.

CAMP 4: THE DIRECT-OVERLAP STARTUPS (watch closely)
  - Pieces for Developers (150k+ developers): OS-level automatic capture, a
    "memory layer that augments other AI tools rather than replacing them." This
    is the closest thing to our thesis that actually shipped at scale — and it
    validates it. BUT: developer-only, and built on OS/screen capture (heavier
    privacy footprint). We win on: connector-first life+work data (not just
    screen), the layered "model of the person" (style/decisions/preferences/
    negatives/relationships), and non-developer users.
  - Supermemory (26.8k stars, MIT core; $2.6–3M seed, Jeff Dean/Cloudflare CTO
    angels; 19-yo founder): "Universal Memory MCP — your memories are in ChatGPT
    but nowhere else; make them available to every LLM." Hosted business
    ($19/$100/$399), sub-300ms retrieval. This is the SAME cross-tool-MCP insight
    we have — the most important competitor to internalize. We win on: (1)
    automatic ingestion of your REAL life data via connectors vs. a generic
    store()/add() API, (2) LOCAL-FIRST / private-by-default vs. cloud-hosted, (3)
    the adaptation layer (style/voice, decisions, relationships) not just a blob
    store, (4) trust/citation/context-firewall as product surfaces.
  Takeaway: the market is validated and moving fast. Our defensible edges are
  local-first privacy + life-data connectors + the adaptation model + trust UX.

CAMP 5: CAPTURE/RECALL & UX EXEMPLARS (learn restraint & trust; note the graveyard)
  - Wispr Flow: voice in, polished text out, everywhere, near-zero UI. The gold
    standard for RESTRAINT — copy the discipline: tiny surface, instant value.
  - Granola: meetings → usable notes. Had a note-link/privacy controversy — proof
    that trust must be a PRODUCT feature, not a settings page.
  - Rewind → Limitless: the cautionary tale. Rewind's local-first "record
    everything" pitch pivoted to a cloud wearable, then was ACQUIRED BY META in
    Dec 2025 and the desktop product was KILLED (capture disabled Dec 19, 2025;
    users in the EU/UK/etc. cut off). Every privacy promise inverted. Users are
    actively fleeing to local-first alternatives (e.g., Screenpipe).
  Takeaway: the most privacy-conscious memory users on earth were just betrayed
  and are looking for a new home RIGHT NOW. Local-first + user-owned + inspectable
  is not a nice-to-have; it's a live, urgent market opening we are positioned for.

THE WHITESPACE NOBODY OWNS (this is us):
  A neutral, LOCAL-FIRST, user-owned personal memory that (a) fills itself
  automatically from the apps you already use, (b) models WHO YOU ARE (style,
  decisions, preferences, relationships, procedures), not just what you said, and
  (c) safely lends that, with citations and permissions, to EVERY AI tool over
  MCP — so switching tools never means starting over.

3. WHAT USERS ACTUALLY WANT
--------------------------------------------------------------------------------
ICPs (lead with the first two):
  1. AI power users / "prompt-tired" knowledge workers who bounce between
     Claude, ChatGPT, and Cursor and are sick of re-explaining themselves.
     JTBD: "stop making me repeat my context, style, and decisions to every AI."
     Willingness to pay: high ($10–20/mo) — they already pay for 2–3 AI tools.
  2. Founders / engineers / builders (our own tribe).
     JTBD: "remember our product decisions, project state, and how I write, and
     feed it to my coding + writing agents automatically."
  3. Consultants / heavy-email knowledge workers; students later.

Universal pains (verified themes):
  - "It forgot." Every AI is a goldfish across sessions and across tools.
  - Re-teaching tax: retyping the same context/persona into each new tool.
  - Setup friction: second-brain apps demand manual organizing nobody sustains.
  - Privacy fear: "I'm not uploading my email/Slack to some startup's cloud."
  - Lock-in fear: after the Rewind/Meta episode, "what happens to my data when
    you get acquired or shut down?"

Magic moments (what actually creates retention — design releases AROUND these):
  - THE moment: you ask Claude/ChatGPT something in YOUR tool, and it answers
    with your real context ("based on your pricing decision from last month...")
    WITHOUT you pasting anything. The AI visibly knows you.
  - "Draft this in my voice" and it actually sounds like you.
  - "Brief me before I talk to Alex" → cited, current, person-scoped context.
  - Opening the app and seeing "here's what I learned this week" — and being able
    to delete any of it in one tap.

Anti-features (what users do NOT want — do not build these):
  - A new inbox of extracted fragments to triage.
  - A manual upload/dropzone as the main flow.
  - Always-on screen/audio surveillance (the Rewind trap).
  - An admin dashboard of toggles.
  - A chatbot that replaces their AI tools (they like their tools).

Strongest single wedge use case to LEAD with:
  "Your AI coding + writing tools, finally aware of your decisions, projects, and
   style — automatically, and only what you allow." (Devs/founders first; it's
   the audience that feels the pain daily and can install an MCP server.)

4. THE VISION — UNIQUE VALUE PROPOSITION
--------------------------------------------------------------------------------
Cortex is the PERSONAL CONTEXT LAYER for the AI era: a private, self-updating
model of you that any AI tool can safely borrow.

Five pillars (each maps to concrete OSS leverage in Section 5):

  PILLAR 1 — NEUTRAL & PORTABLE.
    The one memory that isn't trapped in an app. Works across Claude, ChatGPT,
    Cursor, and whatever's next, via MCP. You own it; you can export/delete it.
    (This is the anti-walled-garden moat.)

  PILLAR 2 — PRIVATE BY DEFAULT (real local semantics).
    Genuine semantic memory that runs ON YOUR MACHINE with NO API key. This is
    both a quality unlock and the trust story that Rewind refugees are looking
    for. (Model2Vec local embeddings + local reranker.)

  PILLAR 3 — SELF-UPDATING & HONEST.
    Memory that expires, supersedes, and detects contradictions — and tells you
    what is CURRENTLY true and can prove it with citations. Append-only memory
    (what everyone else ships) is weak; "knows what's true now" is strong.
    (Graphiti temporal patterns + our existing validity/supersession.)

  PILLAR 4 — A MODEL OF YOU, NOT A LOG.
    Style/voice, decisions+reasons, preferences, negatives, relationships,
    procedures — so agents DRAFT, DECIDE, and ACT like you, not just recall text.
    (Style engine + decision ledger + relationship memory + context-assembly.)

  PILLAR 5 — A CONTEXT FIREWALL.
    Every AI request answers: what was used, from where, why allowed, what was
    withheld, revocable, deletable. Trust is the product. (Permissioned MCP +
    audit + local PII redaction.)

Why we win against free native memory: platforms optimize for lock-in; we
optimize for portability and privacy. They can't see your other tools' data or
your Gmail/Slack/GitHub; we can (with permission), and we carry it everywhere.

6. THE DEAD-SIMPLE PRODUCT (Wispr-Flow discipline)
--------------------------------------------------------------------------------
The whole app is three verbs plus a trust sheet. Nothing else is primary.

  HOME  — one status line ("Cortex knows X things about you across N sources")
          and at most one suggested next action. Never a dashboard.
  REVIEW— a short, high-signal stream of "here's what I learned" (only useful/
          risky/contradictory items surface; approve/forget in one tap). Not an
          inbox to grind.
  ASK   — ask your memory anything; get a cited answer or an honest "I don't
          know that yet." Expandable sources. This is also the demo.
  CONNECTIONS & PRIVACY (one sheet) — connect accounts (OAuth), see source
          health, and control which AI tools can read what. The Context Firewall.

THE FIRST 5 MINUTES (the entire onboarding, zero manual data entry):
  1. Open app. One sentence: "Cortex gives your AI tools a private memory of you."
  2. Connect ONE source you already have (Obsidian folder, or Gmail/Notion via
     OAuth) — one click.
  3. It syncs and shows "I learned 40 things about you" with 3 example memories.
  4. One button: "Turn on memory for Claude / Cursor / ChatGPT" (writes the MCP
     config for them; no JSON, no terminal).
  5. The payoff screen: ask a question in Claude and watch it answer with your
     context. That's the aha. Everything else is optional depth.

SIMPLICITY GUARDRAILS (permanent rules):
  - No vocabulary leaks: never show "MCP", "vault", "shard", "backend", "context
    pack", "embedding" in primary UI. (Show them only in an Advanced drawer.)
  - Complexity is hidden, not removed. The engine is deep; the surface is calm.
  - Every new capability must fit inside Home/Review/Ask/Connections or it
    doesn't ship to the primary UI.
  - Trust actions (see it / delete it / stop using it with AI) are always one tap.

7. THE ROADMAP
--------------------------------------------------------------------------------
Each initiative: WHY (user impact) / BUILD / OSS LEVERAGE / DONE / SIMPLICITY.
Sequenced so the unique value ships early, not after infra.

=== PHASE 0 — MAKE THE MEMORY REAL (2–3 weeks) — the credibility unlock ===

  0.1 Real local embeddings (HIGHEST PRIORITY)
    WHY: today's "semantic" search is hash buckets; this makes it genuinely
         semantic AND keeps it private/offline — our core claim becomes true.
    BUILD: add a "local-neural" embedding provider (Model2Vec potion-base-8M,
           ~8MB) bundled in the app; make it the DEFAULT over hash; keep OpenAI
           as an optional power-user override; add a one-time background re-embed/
           backfill job for existing vaults; keep 384-dim compatibility or manage
           a clean dimension migration.
    OSS: Model2Vec (MIT).  DONE: eval corpus top1/recall@k jumps measurably vs
         hash on a held-out semantic (paraphrase) set; zero network calls; re-embed
         completes on a 10k-memory vault without blocking the UI.
    SIMPLICITY: invisible. No user choice; it just gets smarter.

  0.2 Local reranking
    WHY: precision on "the right memory," especially for personal/ambiguous queries.
    BUILD: add an optional cross-encoder/ColBERT rerank of the fused top-N behind
           the existing rerank stage; gate it on the eval showing lift.
    OSS: answerai-colbert-small-v1 / bge-reranker via fastembed (Apache-2.0/MIT).
    DONE: precision@3 up on the eval corpus with no latency regression >150ms p95.
    SIMPLICITY: invisible.

  0.3 The "AI just got smarter about me" demo path
    WHY: this is the magic moment; it must be a first-class, reliable flow.
    BUILD: one-click "Enable memory for Claude/Cursor/ChatGPT" that writes their
           MCP config for them; a scripted first-answer payoff; instrument
           time-to-first-MCP-context-used.
    OSS: MCP ecosystem.  DONE: a non-technical user reaches a cited cross-tool
         answer in <10 min with no terminal/JSON.
    SIMPLICITY: one button, no MCP vocabulary.

=== PHASE 1 — THE MODEL OF YOU (3–5 weeks) — the differentiator users feel ===

  1.1 Style & Voice engine v2
    WHY: "draft this in my voice" is a daily, sticky use case; platforms can't do
         it well because they don't have your real corpus by context.
    BUILD: per-context style profiles (email vs. code review vs. spec vs. DM),
           phrases-used / phrases-avoided, user-authored-only sourcing; expose via
           get_style_profile + an Ask/MCP "rewrite in my style" path.
    OSS: DSPy to optimize the style-assembly prompt against evals (reference).
    DONE: blind test — users pick Cortex-styled drafts over generic >70% of time.
    SIMPLICITY: shows up only as "sounds like me" in outputs; no config.

  1.2 Decision ledger + self-updating/contradiction memory
    WHY: "what did we decide and why, and is it still true?" — unanswerable by any
         competitor; deeply valuable to founders/teams.
    BUILD: capture reason/constraints/alternatives; explicit supersede; walk
           supersession chains in retrieval; SURFACE contradictions for one-tap
           resolution in Review; answers state confidence (well-known/weak/stale).
    OSS: Graphiti temporal/invalidation patterns (Apache-2.0), local LLM for
         extraction.  DONE: "what replaced decision X?" returns the current one +
         history with citations; contradictions appear in Review.
    SIMPLICITY: contradictions are the ONLY thing that must interrupt; everything
         else stays quiet.

  1.3 Relationship memory v2
    WHY: "brief me before I talk to Alex" — cited, current, person-scoped.
    BUILD: identity resolution incl. aliases, open commitments from tasks, last
           interaction, relevant decisions; get_relationship_context MCP tool.
    DONE: person briefing is cited, current, and cross-source.
    SIMPLICITY: it's just an Ask; no CRM UI.

=== PHASE 2 — EFFORTLESS INPUT & THE FIREWALL (3–4 weeks) ===

  2.1 Frictionless local capture (voice)
    WHY: a Wispr-Flow-grade input surface that ALSO feeds memory — a growth wedge
         and a reason to open the app daily.
    BUILD: global hotkey -> local Whisper transcription -> lands as memory and/or
           drafts in your voice; fully offline.
    OSS: whisper.cpp / faster-whisper (MIT).  DONE: <1.5s to transcribed capture,
         no network.  SIMPLICITY: one hotkey; optional.

  2.2 Context Firewall (trust as product)
    WHY: the trust story that wins Rewind refugees and privacy-first users.
    BUILD: per-answer receipt (used / source / why-allowed / withheld); local PII
           redaction before any AI handoff; per-tool + per-source read permissions;
           one-tap "never use this with AI" and "forget this."
    OSS: Microsoft Presidio (MIT).  DONE: every MCP response carries a receipt;
         redaction verified on a PII corpus; deletion is provably permanent
         (tombstones already exist — extend to hosted fan-out).
    SIMPLICITY: receipts are collapsible; defaults are safe; controls are 1 tap.

  2.3 Import/sync at scale + better chunking
    WHY: "connect your whole life" must not choke or dupe.
    BUILD: streaming, resumable imports; dedupe by source-id + content hash;
           contextual-prefix chunking for long docs.
    OSS: Chonkie (MIT) + contextual-retrieval heuristic.  DONE: a 10k-record
         export imports with 0 dupes and visible progress.

=== PHASE 3 — CONTEXT ASSEMBLY & PERMISSIONED MCP v2 (3–4 weeks) ===

  3.1 Context Assembly Engine
    WHY: the real intelligence — given a task+tool, build the right token-budgeted,
         permissioned, cited context pack (intent -> project -> recency -> trust
         -> constraints), instead of dumping search hits.
    OSS: DSPy to optimize assembly (reference).  DONE: assembled packs beat raw
         search on the eval; every pack is cited and within budget.
    SIMPLICITY: invisible; it just makes every tool's answer better.

  3.2 MCP v2: resources + audit surface
    BUILD: expose resources (style profile, active project, recent decisions, open
           loops, trusted facts, source health); a human-readable "which AI tools
           accessed what" view.  DONE: an app can subscribe to your live context;
           audit view is truthful and simple.

=== PHASE 4 — GROUND FOR 10k & COMMERCIAL (parallelizable, ongoing) ===
  - Distribution: Developer-ID signing + NOTARIZATION (currently missing) + auto-
    update (Sparkle) + opt-in crash reporting. (Blocks real installs.)
  - Accounts + self-serve onboarding on the existing hosted plane; deletion/export
    guarantees with hosted tombstone fan-out.
  - Encryption at rest + secret store for any hosted vaults/tokens.
  - Observability/alerting/backups + incident runbook; keep sharded SQLite (no
    Postgres until >10k or multi-device sync).
  - Billing mapped to the quota scaffolding already built ($10–20/mo prosumer).
  - REFACTOR storage.py from an 18k-line god object into modules (retrieval /
    connectors / memory / audit / hosting) behind the current test suite.

=== PHASE 5 — GUARDED AGENT ACTION (only after trust + quality proven) ===
  - "Prepare + draft + ask approval + execute low-risk + log + rollback" for
    concrete jobs (draft reply, create follow-up, update Linear/Jira, PR context).
  OSS: browser-use / computer-use frameworks, behind hard approval + audit gates.
  DO NOT claim "the agent IS you." Claim: permissioned, cited context that lets
  it work in your style and constraints.

--------------------------------------------------------------------------------
8. MOAT & METRICS
--------------------------------------------------------------------------------
Moat (compounding, hard to copy):
  - Neutrality: the only memory not owned by a model vendor (structural — they
    won't copy it, it's anti-their-business-model).
  - Local-first trust + real local semantics: quality without giving up privacy.
  - Depth of the person-model (style/decisions/relationships/negatives) x breadth
    of connectors: the data flywheel gets more personal the longer you use it.
  - Switching cost that HELPS the user: your memory follows you across tools, so
    leaving Cortex means going back to re-teaching every AI from zero.

North-star metrics:
  ACTIVATION: time-to-first-connected-source; time-to-first-cited-Ask; TIME-TO-
    FIRST-MCP-CONTEXT-USED-BY-AN-EXTERNAL-AI (the real activation event).
  QUALITY: retrieval eval score (semantic held-out set); cited-answer rate;
    abstention correctness; contradiction-resolution rate; "AI knew what I meant"
    self-reports.
  TRUST: memory deletions/corrections used; permission changes; audit views;
    zero credible privacy incidents.

# 4. The Repo-to-Agency Engineering Path

**Principle: agency is not "now the agent can DO things." It is "every action is a
memory of a decision, with the same provenance, the same receipt, the same one-tap
forget."** An action ledger is just the decision ledger with an *execute* step and
a *rollback*. This is why ~90% of the safe action layer is already in the repo —
we re-point the memory-trust machinery at outbound actions rather than build a new
trust layer from scratch.

## 4.1 What exists (verified against HEAD)

- **The cited "why" is done.** `action_brief` (`storage.py:10314`) assembles a
  fully-cited pack: primary context, procedures, **decisions-as-policy-boundary**,
  preferences, **negative constraints**, style, open actions. `agent_adaptation`
  (`storage.py:12038`) emits cited "operate-like-this-user" instructions **with
  the shipped honest-boundary block** ("Do not claim to be the user,"
  `storage.py:12074`).
- **A working human-approval primitive exists.** `approve_capture`
  (`storage.py:11002`) transitions pending→approved and fires an event; the MCP
  gate `approve_memory_capture` (`mcp_tools.py:1742`) is scoped to
  write+maintenance. This is the *only* user-gated approval pattern today — and
  it's the exact shape the action gate needs.
- **The receipt spine exists.** `_event` (`storage.py:18047`) double-writes every
  state change to SQLite **and** the vault (`vault.append_event`,
  `vault.py:238`); `memory_events` (`database.py:194`) is a generic append-only
  table with a free-form `metadata_json` TEXT column. `record_agent_event`
  (`storage.py:14481`) already logs `token_id`, `token_scopes`, success/error —
  the single most undervalued asset in the repo: it is the "trace an action to the
  responsible human" capability the enterprise stack lacks for individuals.
- **Scoped capability tokens exist.** `cxa_/cxm_` tokens + `tools_for_scopes` /
  `_require_tool_access` (`mcp_tools.py:764,775`) gate tools by
  read/write/export/maintenance/destructive.
- **The queue exists and is generic.** `memory_jobs` (`database.py`) has a
  free-form `job_type` string; adding an action job is one line in the dispatcher.

## 4.2 What is MISSING (the KEY GAP, verified)

The 14 connectors (`backend/app/connectors/`) are **fetch-only** — zero write
methods across all of them. There is **no `action_requests` table, no executor, no
`propose_action` tool, no Ed25519** (the only crypto is symmetric HMAC,
`storage.py:14346`). `action_brief` is read-only; nothing consumes an *approved*
brief to produce a side-effect. That gap — the bridge from "memory" to "a self
that acts" — is the hard part and the whole point of Part III.

## 4.3 The smallest first safe action (build ON TOP; no new substrate)

Ship a thin **propose → hold → approve/edit → execute-ONE-reversible-thing →
receipt** ledger:

1. **`propose_action`** (NEW MCP tool, `mcp_tools.py:call_tool` at line 1261).
   Returns: the draft (built from `action_brief`'s *why* + `agent_adaptation`'s
   *voice*) + the exact citations that produced it + **"assumptions I did NOT
   make"** + an approval token. Read-only from the agent's side. Gated on
   write+maintenance scopes, mirroring the `approve_memory_capture` gate.
2. **One Action card** in the existing Review UI — edit-before-approve, a TTL, a
   batch list. Reuses the `approve_capture` pattern as the gate; **no new screen**
   (obeys the Part-II "surface must not grow" law).
3. **On approve, execute exactly ONE reversible, low-blast-radius action** — the
   Gmail *draft* write is the cheapest first executor — then write the receipt.

## 4.4 The approval-gated ACTION LEDGER + receipts (hooked to `memory_events`)

**No new tables in Cortex core.** The ledger is a query over the existing event
stream, using the free-form `metadata_json` on `memory_events`. New event types
flow through the unchanged `_event` signature (`storage.py:18047`):

- `action_drafted` → `object_type='action'`, metadata `{agent_id, task, reason,
  draft_ref, citations, assumptions_withheld}`
- `approval_requested` → `{requester_id, reason}`
- `approval_granted` → `{approver_id, ts, constraints}`
- `execution_started` → `{executor_id, job_id, connector}`
- `execution_result` → `{success, receipt_id, external_ids, prev_hash, hash}`
- `execution_reverted` → `{reverter_id, reason, original_receipt_id}`

The **receipt** is `{what was asked, what was authorized, which cited memories
informed it, what was withheld, what it did, who vouched}`, **hash-chained** over
`memory_events` (`prev_hash → hash`, SHA-256). Single-player needs only
tamper-*evidence*, so the shipped symmetric HMAC seal (`storage.py:14346`)
suffices here — **Ed25519 is deferred to the exact moment a third party must
verify (Rung 4).** Query interface: `action_history(user_id, action_id)` (receipt
chain), `actions_pending_approval(user_id)`, `action_receipts(external_ids[])`
(idempotency: "has an agent already commented on this issue?"). The vault gets a
parallel `append_action_event` writing `vault/actions/{action_id}/events.jsonl`,
so the ledger is durable independent of the `memory_jobs` retention window and
replayable across devices via `sync_change_feed`.

## 4.5 The read-to-write connector path

**Executor-agnostic by design** (so Apple App Intents / MCP clients can dispatch
an approved brief without Cortex becoming a brittle clicker):

- **Credentials:** add a `write` scope alongside the existing read token on the
  `source_accounts` record (`database.py:226`), stored encrypted in the existing
  `metadata` dict — **no schema change.**
- **Execution:** `job_type='execute_action'` dispatched by the `memory_jobs`
  worker to a new `_process_action_job` → connector `execute_*` method. Guarded by
  the gate: an action must be in `approved` state (an event fact, not a new
  column) before the worker claims it.
- **Idempotency:** `stable_id('act_', user + connector + target + type + params)`
  as the job `unique_key` prevents double-execution; the `action_receipts` lookup
  is checked before re-run.
- **Prompt-injection is a first-class UI state:** any draft whose assembled
  context included **agent-ingested external content** (an email body, a fetched
  README) is flagged in the receipt — *"influenced by content you didn't
  write"* — and treated as untrusted. This directly answers the 31–50% hijack
  rate; the receipt becomes a **security** surface, not just a provenance one.

# 6. The Interop Long-Game (why sequenced last)

**PCP grows from a memory-portability format (commoditized — the Solid trap) into
the IDENTITY / CONTEXT / TRUST layer between personal selves** — the "who is this
agent, whose intent does it carry, is that intent current and truly theirs, and
can you prove what it did" layer that the entire 2026 interop stack (A2A signed
Agent Cards, AP2 mandates, ERC-8004 passports, enterprise IAM) left **"absent
entirely" for individuals** (arXiv 2604.23280). PCP is **not a competing
transport** — it is a signed **payload + attestation** that travels *inside*
A2A/MCP/AP2 rails, in three parts, each an emit/attest layer over shipped code:
**(1) the Personal Mandate** (local Ed25519-signed, scoped, time-bound, trust
derived from the person's own cited memory + a human vouch — a position the
central-issuer IAM camp and the on-chain-passport camp structurally cannot
occupy); **(2) the Context Digest** (minimal, cited, current-truth constraints,
not raw history — the anti-surveillance-pricing artifact); **(3) the Receipt
Chain** (`record_agent_event` extended to answer "trace this action to the
responsible human" — which only 28% of orgs can).

**The network effect is real but must be earned ASYMMETRICALLY first.** Stage 1 is
zero-network: my self → ONE business's agent, which needs no other Cortex users
and whose counterparty already *exists and is desperate for it* (agentic commerce
is blocked by mutual distrust; merchants need "verify the agent, not just the
user"). Stage 2 is the **emitter moat**: the durable advantage is not the protocol
(copyable) but being the only *trustworthy emitter*, because trust flows from the
local, cited, user-owned memory nobody else has — and a model vendor will **never**
author an anti-lock-in personal-mandate standard (that neutrality is structural).
Stage 3 — **peer-to-peer, dead last** — is where the two-sided network effect
finally kicks in, only after asymmetric acceptance has seeded the format and the
single-user loop is deeply trusted.

**Why sequenced last** (this is the single most important correct call in the
strategy): (a) PCP's entire moat is that trust flows from local, cited, user-owned
memory — so **real local embeddings (P0)** and **falsifiable voice + current-truth
(P1)** must land first or every interop claim is a lie; (b) a "mandate to act" has
**nothing to execute** until the action surface exists (P3+) — issuing mandates
before a gated action ledger is the identity cart before the action horse; (c)
**true peer-to-peer has zero counterparties in 2026** — building it now is a
standard nobody imports, the Solid death. Leading with "protocol" is the graveyard;
we don't say the word externally until self-adoption inside Cortex is the proof.


# 7. Moat + Metrics (trust, fidelity, agency-success — not vanity)

## 7.1 The moat

- **The emitter moat:** trust flows from a **local, cited, user-owned memory** no
  one else has. Anyone can copy a JSON schema; no one can copy the fidelity that
  makes a Cortex mandate worth accepting.
- **The provenance moat:** a per-action, hash-chained receipt (what was asked,
  authorized, cited, withheld, done, who vouched) — the one artifact that makes
  delegated action trustworthy, and the one thing frontier labs structurally
  cannot offer an *individual*.
- **The neutrality moat (structural):** Apple won't unify your Cursor + Claude
  Code + ChatGPT + Gmail context because each rival won't feed a competitor's OS;
  a neutral third party is the only one who *can* — and this is structural, not a
  feature an incumbent can copy without cannibalizing its own lock-in.
- **The honesty moat:** citations-or-abstain + the honest-boundary block +
  "acts FOR you, disclosed" is the anti-companion, anti-drift discipline the whole
  category will be regulated *against*. Under-promise is the moat.

## 7.2 Metrics (measure trust and earned agency; never save-hours theater)

- **Fidelity:** blind "sounds like me" rate (gate: >70%). **Retrieval recall@k on
  paraphrases** vs the hash baseline (gates P0).
- **The North Star safety metric:** the **"wrong-in-my-voice" incident rate** —
  instrumented and driven toward zero; a single confident-error-in-your-voice to a
  real relationship is fatal, so this, not hours-saved, is the headline.
- **Agency success:** on Rung 1, the **send-unedited / lightly-edited rate**
  (do they actually send it?); **edit-vs-verbatim rate per action-class** (the
  gate that promotes up the ladder).
- **Trust:** near-zero correction rate on a standing-permission class before Rung 2
  unlocks; **undo-invocation rate** (low = trusted; a spike = a rung was granted
  too early).
- **Revealed WTP:** paid conversion behind the $20/mo wall — never the 3.2x survey
  number.
- **Sovereignty-in-fact:** % of core flows that work **offline with no API key**
  (must reach 100% for the memory/brief path before the continuity claim ships).


# 8. What NOT to Build / Claims to Avoid / Safety + Liability Guardrails

## 8.1 What NOT to build

- **The hash-vector "semantic memory" default — KILL immediately.** It makes "a
  model of you" false and "private semantic memory" false-without-a-cloud-key
  simultaneously. A fraud to remove before any "acts as me" claim (`embeddings.py`
  default `"hash"`).
- **Any autonomous send / publish / spend / delete — KILL permanently (invariant,
  not a phase).** The instant Cortex auto-sends, the deployer inherits liability;
  one confident-error-in-your-voice destroys the moat. **Irreversibility +
  autonomy must NEVER combine.**
- **Browser / computer-use as the action surface — KILL.** The frontier proved it
  unshippable (Operator + Mariner dead; ~20% long-horizon; 31–50% injection).
  Connector-write draft-and-hold instead; be the brief that feeds any executor.
- **The face / voice / avatar — KILL** as anything but a thin optional skin. A
  realistic avatar that lacks judgment or lies ("I checked your calendar") is more
  unsettling and more dangerous than text; it's also the regulatory blast radius.
- **"Sovereign" / "own your data" as the acquisition hook — DEFER to subtext.**
  The privacy paradox is ironclad; convert on a working draft, retain on
  sovereignty.
- **PCP / "protocol" / peer-to-peer negotiation as anything near-term — DEFER hard
  to Rung 4+.** Zero network in 2026; leading here is the Solid death.
- **Multi-persona / "clone you rent to your audience" — KILL.** That's Delphi's
  outbound-broadcast job — opposite direction, different market. Cortex is the
  private, inbound, does-YOUR-work self.
- **The trust-score dial + the wall of scope toggles + Review-queue-first
  onboarding — DEFER to an Advanced drawer / replace with the mirror moment.**
  Collapse the felt controls to the receipt and the Undo.

## 8.2 Claims to avoid (marketing discipline is a live risk, not a solved one)

- "The AI they can't switch off" → Cortex depends on external Claude/GPT to reason;
